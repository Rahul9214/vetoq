# UI and UX contract

This is the production visual and truthfulness direction. It is not a claim that the current screens are the finished design. Capability status lives only in [PRODUCT_CONTRACT.md](PRODUCT_CONTRACT.md).

## Quality

The interface is premium, modern, sleek, architectural, high-end, distinctive, responsive, and accessible.

The public site and the operations console share this language and use different layouts. Reference images are quality and composition references. They are not layouts to copy.

## Color

Canonical families: paper, warm ivory, stone, champagne, ink, graphite, lavender, plum, copper, coral, amber, and rose.

ALLOW, REVIEW, and BLOCK may use separate accessible semantic colors. Those colors are not the brand.

Do not make the product dominantly dark, blue, or green. Do not use generic AI gradients, chatbot layouts, robot, brain, or sparkle motifs, a default shadcn dashboard, excessive glassmorphism, or repeated identical rounded cards.

The current stylesheet still contains charcoal panels and custom layout rules. That is foundation debt, not permission to expand a dark or green theme.

## Structure

- Editorial typography: a readable sans for prose and a monospace for identifiers, digests, and state names. Do not require a remote font.
- Architectural grids, modular filled regions, and controlled asymmetry.
- Motion explains a state change. Honor reduced motion.
- The console may use a restrained terminal-like evidence presentation. It is not a chat transcript.
- Sections may change surface color. Navigation and footer stay deliberate and quiet.
- Progressive disclosure keeps review, evidence, and errors reachable. Do not hide overflow to mask a broken layout.

## Truthfulness

Every visible operational state comes from the API or from a deterministic reading of persisted fields.

- Goal Lock is sealed when an envelope exists. It is not verified merely because it is displayed.
- Source and findings are recorded or absent. They are not a security clearance.
- A proposal is proposed, or it shows the Action Guard verdict. It is not pending after the action row exists.
- A ticket is verified only when `verified_at` is present.
- Review controls appear only when the API says the caller is eligible.
- Illustrations are labeled as illustrations. They are not live telemetry.

Status is text plus a symbol. Color is not the only signal.

## Release bar

Required CSS widths remain 320, 360, 390, 430, 768, 1024, 1280, 1440, and 1920. Accessibility targets WCAG 2.2 AA: semantic headings and controls, keyboard access, visible focus, contrast, reduced motion, and reflow. Automated checks do not by themselves prove conformance. Performance numbers in older design notes are targets, not measured results.
